# RAG Implementation Spec - Consultant Selection Assistant

## 1. Objective

Build a production-style MVP vertical slice that:
- accepts a role input (role_id or free-text job posting)
- retrieves and scores consultant candidates
- generates grounded explanations using retrieved evidence
- returns a deterministic ranked shortlist suitable for human review

This implementation spec is aligned to:
- `MVP-Spec.md`
- `02_Copy_Paste_Architecture_Blueprint_RAG_Agentic_Hybrid.md`
- `dataset/starter_task_brief.md`

## 2. Scope

### In scope (this build)
- local data loading from provided CSV files
- schema normalization and alias handling
- hybrid retrieval (rule filter + lexical similarity)
- deterministic scoring and ranking
- RAG explanation generation from retrieved profile evidence
- machine-readable output contract
- basic evaluation and smoke tests

### Out of scope (this build)
- web UI implementation
- live ATS or HRIS integrations
- auth/RBAC
- online learning or retraining loops
- full fairness dashboard

## 3. Definition of Done Mapping

The MVP is complete when all checks below pass.

1. Happy path runs end-to-end from role input to ranked output.
2. Output includes actionable recommendation.
3. Output includes confidence or rationale signal.
4. At least one source citation is included in each run.
5. Response time is stable for demo usage.
6. Top 5 includes matched skills and explicit gaps per candidate.
7. Human-review-required flag is produced when confidence is below threshold.

## 6. System Design (Hybrid-Lite)

1. Parse role input into normalized constraints.
2. Retrieve top K candidate pool using normalized skill/domain/cert matches.
3. Apply hard constraints from must-have rules.
4. Compute deterministic weighted fit score.
5. Select top N candidates.
6. Retrieve evidence snippets per top candidate.
7. Generate grounded rationale using LLM with strict JSON output.
8. Produce final response contract and logs.

## 8. Scoring Specification

Use deterministic weighted scoring from `MVP-Spec.md`:
- required_skills: 40
- required_certs_tools: 15
- domain: 12
- preferred_skills: 10
- experience: 8
- behavioral: 8
- availability_location: 5
- prior_rating: 2

Total score range: 0-100.

### Hard rule behavior
- If must-have constraint fails: exclude candidate or cap to bottom with `CONSTRAINT_FAIL_*` flag.
- If required skill coverage is below 0.60: candidate cannot appear in top 3 unless override is explicitly logged.

## 9. Retrieval Specification

### Candidate retrieval
- Input: normalized role object.
- Output: top K consultants with retrieval score.
- Method:
  1. Pre-filter by obvious hard logistics (date/location when explicit).
  2. Compute overlap on required skills, preferred skills, certs, and domain.
  3. Add lexical match over resume_text and project tags.
  4. Return top K (default 25).

### Evidence retrieval
- For each top candidate, return 3-6 snippets proving matches/gaps.
- Include snippet provenance (field or resume source).

## 10. RAG Prompt Contract

Prompt must enforce:
- use only provided evidence snippets and normalized role constraints
- no new facts
- JSON-only response
- explain rank, strengths, gaps, risk flags in concise language

Fallback rule:
- if model output fails parse, use deterministic template rationale and return parser warning in limitations.

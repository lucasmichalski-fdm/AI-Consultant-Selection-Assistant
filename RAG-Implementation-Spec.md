# RAG Implementation Spec - Consultant Selection Assistant

## 1. Objective

Build a production-style MVP vertical slice that:
- accepts a role input (role_id or free-text job posting)
- discovers potentially relevant consultant candidates in batches
- evaluates each candidate-role pair into a standardized Evaluation Packet
- applies deterministic scoring and ranking over Evaluation Packets
- compares and explains ranked output for recruiter decision support
- generates role-positioning and upskilling guidance for selected consultants
- generates grounded explanations using retrieved evidence
- returns a deterministic ranked shortlist suitable for human review

This implementation spec is aligned to:
- `MVP-Spec.md`
- `02_Copy_Paste_Architecture_Blueprint_RAG_Agentic_Hybrid.md`
- `dataset/starter_task_brief.md`

## 2. Scope

### In scope (this build)
- local data loading from provided CSV files
- schema normalization and alias handling
- hybrid retrieval (rule filter + lexical similarity)
- componentized model pipeline with explicit boundaries:
  - candidate-discover
  - candidate-fit-evaluator
  - deterministic-scoring-agent
  - rank-comparison-agent
  - resume-upskill-advisor
- deterministic scoring and ranking
- dual-tier evidence matching (`confirmed` vs `potential_unconfirmed`)
- RAG explanation generation from retrieved profile evidence
- machine-readable output contract
- basic evaluation and smoke tests

### Out of scope (this build)
- web UI implementation
- live ATS or HRIS integrations
- auth/RBAC
- online learning or retraining loops
- full fairness dashboard

## 3. Definition of Done Mapping

The MVP is complete when all checks below pass.

1. Happy path runs end-to-end from role input to ranked output.
2. Output includes actionable recommendation.
3. Output includes confidence or rationale signal.
4. At least one source citation is included in each run.
5. Response time is stable for demo usage.
6. Top 5 includes matched skills and explicit gaps per candidate.
7. Human-review-required flag is produced when confidence is below threshold.
8. Potential (unconfirmed) relevance is surfaced separately and never treated as confirmed requirement coverage.

## 6. System Design (Componentized Hybrid)

1. Parse role input into normalized constraints.
2. candidate-discover analyzes candidate batches and returns top K potentially relevant consultants.
3. candidate-fit-evaluator processes one consultant against one role and emits an Evaluation Packet.
4. deterministic-scoring-agent consumes Evaluation Packets, applies hard constraints + weighted scoring, and ranks.
5. rank-comparison-agent explains ordering decisions among ranked consultants using deterministic evidence.
6. resume-upskill-advisor generates improvement guidance for selected consultants using confirmed gaps and potential signals.
7. Produce final response contract and logs.

### 6.1 Component responsibilities

1. candidate-discover
- Input: role + consultant batch
- Output: shortlist of potentially relevant consultant_ids with retrieval metadata
- Behavior: maximize recall, avoid final fit assertions

2. candidate-fit-evaluator
- Input: one role + one consultant
- Output: standardized Evaluation Packet
- Behavior: gather confirmed evidence, detect potential-unconfirmed signals, compute component-level deterministic facts

3. deterministic-scoring-agent
- Input: list of Evaluation Packets
- Output: ranked candidates with fit_score, score_components, score_attribution, reason_codes, risk_flags
- Behavior: authoritative scoring and ordering layer; no hallucinated evidence

Score attribution semantics:
- `raw_weighted_dimensions` is the full weighted score breakdown and sums to fit_score (subject to rounding).
- `canonical_requirement_groups` decomposes only requirement-related dimensions (`required_skills` and `required_certs_tools`).
- `canonical_weighted_points_total` is expected to match `requirement_dimension_points_total`, not `overall_fit_points_total`.
- `requirement_canonical_rounding_delta` captures tiny rounding drift between these two requirement totals.
- `attribution_model` must be `canonical_groups_decompose_requirement_dimensions` to make this scope explicit for downstream consumers.

4. rank-comparison-agent
- Input: ranked candidates + Evaluation Packets
- Output: concise comparison rationale (why rank A over rank B)
- Behavior: explanation only, no score mutation

5. resume-upskill-advisor
- Input: selected consultant + target role + Evaluation Packet
- Output: realistic upskill opportunities, resume-strengthening suggestions, interview talking points
- Behavior: must separate confirmed gaps from potential relevance and avoid over-claiming competence

## 8. Scoring Specification

Use deterministic weighted scoring from `MVP-Spec.md`:
- required_skills: 40
- required_certs_tools: 15
- domain: 12
- preferred_skills: 10
- experience: 8
- behavioral: 8
- availability_location: 5
- prior_rating: 2

Total score range: 0-100.

### Hard rule behavior
- If must-have constraint fails: exclude candidate or cap to bottom with `CONSTRAINT_FAIL_*` flag.
- If required skill coverage is below 0.60: candidate cannot appear in top 3 unless override is explicitly logged.

### Evidence-tier behavior
- `confirmed` evidence sources: normalized structured fields and exact normalized phrase matches in free text.
- `potential_unconfirmed` evidence sources: related-term hints, partial token overlap, and soft lexical similarity.
- Only `confirmed` evidence can satisfy requirements or increase score components.
- `potential_unconfirmed` evidence must be emitted as review guidance only.
- candidate-fit-evaluator is the authoritative producer of this evidence-tier split inside Evaluation Packets.

## 9. Retrieval Specification

### Candidate retrieval
- Input: normalized role object.
- Output: top K consultants with retrieval score.
- Method:
  1. Pre-filter by obvious hard logistics (date/location when explicit).
  2. Compute overlap on required skills, preferred skills, certs, and domain.
  3. Add lexical match over resume_text and project tags.
  4. Return top K (default 25).

### Candidate discovery contract
- candidate-discover receives consultant records in batches from the application.
- It returns potential relevance only (high recall), plus retrieval metadata for traceability.
- It does not assign final fit or clear requirements.

### Evidence retrieval
- For each top candidate, return 3-6 snippets proving matches/gaps.
- Include snippet provenance (field or resume source).

## 10. RAG Prompt Contract

Prompt must enforce:
- use only provided evidence snippets and normalized role constraints
- no new facts
- JSON-only response
- explain rank, strengths, gaps, risk flags in concise language
- keep strict distinction: potential signals are tentative and never asserted as confirmed requirement coverage

Additional prompt contracts:
- rank-comparison-agent must explain ordering deltas using score components, constraints, and evidence tiers only.
- resume-upskill-advisor must recommend only realistic next-step upskilling, clearly label prerequisite gaps, and avoid implying mastery where evidence is unconfirmed.

Fallback rule:
- if model output fails parse, use deterministic template rationale and return parser warning in limitations.
